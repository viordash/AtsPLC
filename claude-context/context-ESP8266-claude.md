# ESP8266

Единственная платформа проекта. Прошивка собирается ESP8266_RTOS_SDK, тулчейн лежит в `SDK/`.

## Сборка

```bash
make web          # один раз после правок фронтенда: npm install && ng build
make app          # прошивка
make tests        # юнит-тесты
```

Всё это обёртки над `make -C PLC_esp8266` и `make -C Tests_esp8266`.

Переменные окружения для прямого вызова:

```bash
export IDF_PATH=<repo>/SDK/ESP8266_RTOS_SDK
export PATH=<repo>/SDK/xtensa-lx106-elf/bin:$PATH
```

**Зависимости от заголовков сборка не отслеживает.** После правки любого `.h` перед `make app`
нужно `rm -rf PLC_esp8266/build/main`, иначе линковка падает на устаревших `.o` или, хуже,
проходит со старым кодом. Тестовая сборка зависимости отслеживает.

`Tests_esp8266/Makefile` подключает `PLC_esp8266/main/component.mk`, поэтому все `-D` из
`CPPFLAGS` доезжают до тестов.

## Разделы flash (`partitions.csv`)

```
nvs         0x9000   0x4000
otadata     0xD000   0x2000
phy_init    0xf000   0x1000
ota_0       0x10000  0x100000
ota_1                0x100000
storage_0            0x20000
storage_1            0x20000
backups              0x80000
```

`storage_0` и `storage_1` - две копии одних и тех же данных, `redundant_storage` пишет в обе
и читает ту, у которой сходится crc32. `backups` держит 4 слота программ сервисного режима.

## Дисплей

OLED 128x64 на ssd1306, шина I2C. Кадр собирается в `FrameBuffer` целиком и отдаётся
одним вызовом `end_render`, если `has_changes` взведён.

| Что | Значение |
|-----|----------|
| Разрешение | 128x64 |
| Высота строки шрифта 6x12 | 12 px |
| Видимых сетей | 2 |
| Строк в `ListBox` | 4 видимых, ёмкость 8, прокрутка + `ScrollBar` |

`peek_framebuffer()` отдаёт текущий кадр без очистки - через него web-интерфейс читает картинку.

## GPIO и события

Кнопки и вход работают через одну `EventGroupHandle_t` (`Controller::gpio_events`).

| Бит | Событие |
|-----|---------|
| BIT0 / BIT1 | UP закрыта / отпущена |
| BIT2 / BIT3 | DOWN закрыта / отпущена |
| BIT6 / BIT7 | SELECT закрыта / отпущена |
| BIT8 / BIT9 | вход D1 замкнут / разомкнут |
| BIT10 / BIT11 | смена режима работы (`WORK_MODES_0` / `WORK_MODES_1`) |
| BIT15 | пробуждение задачи контроллера |

События режима работы поднимает `WorkModeController` - смена происходит в задаче контроллера,
а не в задаче HTTP.

## Задачи

| Задача | Что делает |
|--------|------------|
| `ctrl_actions_task` | цикл контроллера: опрос входов, `Ladder::DoAction`, запись выходов |
| `ctrl_render_task` | отрисовка кадра |
| `wifi_task` | обработка очереди запросов WiFi |
| `datetime_task` | SNTP и сохранение времени в RTC |

## RTC-память

`hotreload_service` держит в RTC RAM состояние, которое должно пережить программный
перезапуск: признак горячего старта, счётчик перезапусков, положение вьюпорта и выбранную
сеть, текущее время, признак Debug. Целостность - магическое число плюс crc32.
